# Phone BLE discovery and GATT

Selective AGPL-3.0 port from charlesreid1/M0MA-V3SP3R at 62c189ca54a291ab3b35670b2fa79f236d2331f1. Commands use the phone adapter and separate connections, independent of Flipper. Scan, enumerate, read, write, and notification collection are bounded. Writes and CCCD subscriptions always enter existing explicit approval even when HIGH auto-approval is enabled. Missing permissions fail without device work. Cancellation propagates and connections close; pending callbacks are cleared; ambiguous characteristic UUIDs fail closed.

Use `ble_scan_targets` (duration seconds, optional command=name filter), `ble_enumerate` (address), `ble_read_char` / `ble_write_char` / `ble_subscribe` (address and full uuid). Write content is hex by default; `hex=false` uses UTF-8. At most 512 bytes per write and 256 scan results/notifications. No-response writes additionally require the payload to fit the negotiated MTU minus 3 (20 bytes if negotiation is unavailable); oversized payloads fail without sending bytes. GATT queue waiting is bounded by the requested timeout. The approval reason shows the target address, full characteristic UUID, exact payload in hex, write mode, or subscription duration. Subscription setup first reads the remote CCCD and restores that value before closing, including cancellation; restoration gets a separate 3-second deadline and an unconfirmed restore is reported as failure.

Hardware validation required: Android 30/31/33 permission revocation, remote disconnect, descriptor failure, connection cancellation and target read/write/notification. These hardware checks have not been performed; automated tests do not establish peripheral behavior.

When combining with the generated-schema PR, update its explicit action/argument manifest and run `:app:generateExecuteCommandSchema` followed by `:app:verifyExecuteCommandSchema`. The build intentionally fails on unreviewed schema drift.
